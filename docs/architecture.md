# ai-notes 架构

ai-notes 是面向个人的本地优先笔记应用：数据像 Obsidian 一样留在自己的 Markdown 文件里，AI 回答必须带出处，能力通过插件扩展。本文是 P0 的架构约定。插件 API 当前是 **preview v1**，1.0 之前还允许调整形状。

## 产品定位

目标用户是学生、研究者、开发者和写作者。桌面端（Tauri）优先，Web 端复用同一套前端；移动端放到后面。

核心免费。付费项是端到端加密同步、托管的 AI 额度和高级插件。不开启同步也能完整使用。

| 痛点                | 做法                                                                 |
| ------------------- | -------------------------------------------------------------------- |
| AI 记不住上下文     | 笔记库就是记忆：自动索引，提问时检索注入；另有可见、可编辑的记忆卡片 |
| 回答会幻觉          | 回答附引用，点击跳到原笔记；没有依据时直说                           |
| AI 和工作流是断开的 | 选中即可改写，回答可以存成笔记，插件可以接外部工具                   |
| 成本和隐私          | 文件只在本地；可以用自己的 API Key 或本机 Ollama                     |
| 工具太散            | 剪藏、模板、任务等收成插件                                           |

## 系统分层

本地文件是唯一事实来源，索引随时可以重建。云端全部可选。内核保持很小，编辑器之外的功能走插件 API，官方功能也走同一套 API。

```text
客户端 UI          React：文件树、编辑器、AI 面板、图谱、插件中心
    │
Core 内核          Vault、文档模型、事件总线、命令系统
    │
插件宿主           沙箱、权限、Plugin API
    │
本地索引           SQLite FTS5 + sqlite-vec
    │
AI 服务 + 模型路由  检索增强、记忆、工具调用、多模型
    │
本地文件系统       Markdown 和附件
    ├────────────── 模型提供方（云端 API 或本机 Ollama）
    └────────────── 可选云服务（账号、加密同步、托管额度、插件市场）
```

UI 调用 Core 和插件宿主。Core 读写文件并增量更新索引。插件只能通过受控 API 碰到 Core 和 AI。AI 从索引检索，再把请求交给模型路由。只有用户打开同步时，Core 才接触云服务。

## 模块与负责人

| 模块         | 职责                                       | 关键点                                   | 负责人      |
| ------------ | ------------------------------------------ | ---------------------------------------- | ----------- |
| Vault        | 笔记文件夹、文件监听、增删改名、附件       | 改名时更新双链；能打开已有的 Obsidian 库 | 前端        |
| 编辑器       | Markdown 编辑与预览、双链、标签、块引用    | CodeMirror 6，扩展点开放给插件           | 前端        |
| 链接与图谱   | `[[链接]]`、反向链接、知识图谱             | AI 建议的关联用虚线表示                  | 前端 + UI   |
| 索引服务     | 全文、分块、向量、元数据                   | 后台增量，不阻塞界面                     | 后端        |
| AI 服务      | 检索增强问答、记忆、编辑器内指令、工具调用 | 回答必须带引用                           | 后端        |
| 模型路由     | 统一封装多家模型，失败时降级，记录用量     | 自带 Key、托管额度、本地模型             | 后端        |
| 插件宿主     | 加载、沙箱、权限、生命周期                 | manifest 声明权限，安装时授权            | 前端        |

| 设置与记忆页 | 模型配置；查看、修改、删除记忆卡片         | AI 记住了什么对用户可见                  | 前端 + UI   |
| 云服务（P2） | 账号、端到端加密同步、额度、插件市场       | 放在独立的服务端                         | 后端 + 运维 |

插件 API、数据模型和这份文档由架构负责，评审时以此为准。

## AI 检索与记忆

1. **写入。** 笔记保存后发出事件。索引按标题和段落切块，大约 500 字一块，记下所属笔记和位置。
2. **索引。** 块写入 FTS5。嵌入模型（本地或云端）生成向量，写入 sqlite-vec。只重算改过的块。
3. **提问。** AI 面板带上当前笔记作为默认上下文。
4. **混合检索。** 关键词和向量分别取回结果，合并排序，再加上双链邻近度和记忆卡片，留下前面的若干块。
5. **生成。** 模型路由选择模型。提示词要求按块编号标注引用。
6. **呈现。** 回答下面列出被引用的笔记，点击跳到原文位置。可以存成新笔记，或插入当前笔记。
7. **记忆卡片。** 从当前笔记或选中文本生成问答 / 挖空卡，用户确认后才保存；笔记里也可以按约定语法手写。卡片是 `记忆/*.md`，SM-2 排期写在同一份文件里。格式、降级和来源笔记改名、删除时的行为见 [cards.md](cards.md)。

## 插件体系

规范在 `packages/plugin-sdk`，版本号是 `preview-v1`。一个插件是一个目录：`manifest.json`、打包后的 `main.js`，可选 `styles.css`。清单的 JSON Schema 在 `packages/plugin-sdk/schema/manifest.schema.json`。

权限在安装和升级时确认。升级如果新增权限，要再次展示差异。

| 权限          | 允许的操作                                              |
| ------------- | ------------------------------------------------------- |
| `vault:read`  | 读取笔记。可以用 `folders` 限制到若干文件夹             |
| `vault:write` | 创建、修改、删除、重命名笔记。preview v1 不按文件夹缩小 |
| `ai:invoke`   | 调用对话和补全，计入用户额度                            |
| `network`     | 访问清单里声明的域名。沙箱不能自己发请求，由宿主代发    |
| `ui:panel`    | 侧栏、标签页、状态栏、设置页                            |
| `clipboard`   | 读写剪贴板文本                                          |

社区插件跑在独立的 iframe（带界面）或 Web Worker（纯逻辑）里，通过 `postMessage` 上的 RPC 和宿主说话。协议名是 `ai-notes.plugin-rpc`。插件看不到文件系统，也看不到其他插件。官方插件走同一套 API。

进程内的回调（命令函数、CodeMirror Extension、工具处理函数）不会放进 RPC 载荷。宿主需要执行它们时，向沙箱发送对应的请求，例如 `command.invoke`、`editor.renderCodeBlock`、`ai.tool.call`。CodeMirror 扩展在 preview v1 只提供给同进程插件；沙箱插件用代码块渲染器和 manifest 里的编辑器声明。

扩展点：

| 扩展点   | 作用                                                                           |
| -------- | ------------------------------------------------------------------------------ |
| 命令     | 命令面板条目和快捷键                                                           |
| 视图     | 侧栏面板、独立标签页、状态栏、设置页                                           |
| 编辑器   | CodeMirror 扩展                                                                |
| 渲染     | 自定义代码块，例如 mermaid                                                     |
| AI 工具  | 注册成助手可以调用的工具                                                       |
| 导入导出 | 网页剪藏、从别的格式导入、导出                                                 |
| 事件     | `note:created`、`note:modified`、`note:opened`、`note:renamed`、`note:deleted` |

插件入口是一个 `Plugin` 子类，或者 `definePlugin({ onload, onunload })`。宿主的顺序是：检查 `minAppVersion` 和权限，创建沙箱，构造插件，调用 `onload`；禁用或卸载时调用 `onunload`，再释放 `ctx.subscriptions`。

v1 的分发方式和 Obsidian 早期一样：一个 GitHub 仓库维护插件索引 JSON，客户端按 release 安装。这个索引还没做，现在是把插件目录复制进 `<vault>/.ainotes/plugins/<id>/`。P2 再做带审核和评分的市场。仓库里已有的示例是 `plugins/word-count`、`plugins/daily-notes`，以及打开库时写入的 `hello-notes`。网页剪藏、模板和 AI 摘要还没有做。写法见 `docs/plugins/`。

## 数据模型

库文件在 `<vault>/.ainotes/index.db`。完整 DDL、索引和触发器见 [schema.sql](schema.sql)。

| 表                           | 主要内容                                   | 能否从文件重建   |
| ---------------------------- | ------------------------------------------ | ---------------- |
| `notes`                      | 路径、标题、内容哈希、时间、frontmatter    | 能               |
| `chunks`                     | 所属笔记、标题路径、起止偏移、文本         | 能               |
| `chunks_fts`                 | FTS5 虚表，外部内容指向 `chunks`           | 能               |
| `chunk_vectors`              | sqlite-vec 的 `vec0` 虚表，需加载扩展      | 能               |
| `links`                      | 来源笔记、目标路径、种类                   | 能               |
| `tags`                       | 笔记和标签                                 | 能               |
| `memories`                   | 范围、内容、来源、状态                     | 否               |
| `conversations` / `messages` | 对话；消息上的 `citations` 是 JSON         | 否               |
| `plugins`                    | 版本、是否启用、已授予权限、设置           | 否               |
| `usage`                      | 日期、提供方、模型、功能、输入和输出 token | 否（只影响统计） |

不能从文件重建的对话和插件设置，另外写成 `.ainotes/` 下的 JSON。删掉 `index.db` 之后，用文件重建索引，再把这两份 JSON 导回去。记忆卡片不进 `memories` 表：正文和排期都在 `记忆/*.md`，会和其他笔记一起重建。

`chunks_fts` 使用 trigram 分词，中英文都可以做子串检索，但短于 3 个字符的查询匹配不到。这是索引策略，不是文件格式，可以在重建索引时更换。

`chunk_vectors` 的维度在建表时确定。首发按本地模型 `nomic-embed-text` 的 768 维来建；更换嵌入模型就丢掉这张表重建。`vec0` 不支持外键，删除分块时索引服务要自己删掉向量。

## 技术选型

| 层           | 选型                                                    | 理由                                             |
| ------------ | ------------------------------------------------------- | ------------------------------------------------ |
| 桌面壳       | Tauri 2                                                 | 体积和内存都小；Rust 侧负责文件、SQLite 和钥匙串 |
| 前端         | Vite + React + TypeScript                               | 不需要服务端渲染；Web 版共用                     |
| 编辑器       | CodeMirror 6                                            | 直接改 Markdown 原文，扩展点清晰                 |
| 状态         | Zustand                                                 | 轻，插件可以订阅                                 |
| 本地数据库   | SQLite + FTS5 + sqlite-vec                              | 一个文件，全文和向量放在一起                     |
| Web 存储     | File System Access API，不行再退到 IndexedDB            | 浏览器里尽量仍是真实文件夹                       |
| AI           | TypeScript 模型路由，兼容 OpenAI 协议、Claude 和 Ollama | 换模型不改业务代码                               |
| 云服务（P2） | Node（Fastify）+ PostgreSQL + 对象存储                  | 与客户端同语言；同步的是密文                     |
| 工程         | pnpm workspace + Turborepo，GitHub Actions              | 多包一起构建和检查                               |

## 安全与隐私

1. API Key 放在系统钥匙串里，不写进笔记目录，也不进同步。
2. 发给云端模型的内容在设置里可以查看，并可以按文件夹排除。例如日记目录永不发送。
3. 插件默认没有任何权限。网络权限必须写明域名；宿主代发请求并核对主机名。
4. `vault:write` 在 preview v1 覆盖整个库，安装界面要把这一点写清楚。
5. 同步是端到端加密，服务端只存密文。
6. 默认不收集笔记内容。崩溃和使用统计要用户自己打开。
7. 插件之间不共享内存。RPC 只接受约定的信封，来源不对的 `postMessage` 直接丢掉。

## 仓库结构

```text
apps/desktop          Tauri 壳，以及文件、SQLite、钥匙串的 Rust 命令
apps/web              Web 入口
packages/core         Vault、文档模型、事件总线、命令系统
packages/editor       CodeMirror 扩展
packages/indexer      分块、全文和向量
packages/ai           检索增强、记忆、模型路由
packages/plugin-host  沙箱、权限检查、RPC
packages/plugin-sdk   给插件和宿主用的类型、清单 schema、RPC 信封
packages/ui           设计系统
plugins/*             官方插件
server                P2 的同步和账号服务
docs/architecture.md  本文
docs/schema.sql       本地索引 DDL
```

`packages/plugin-sdk` 只描述契约，不读取磁盘，也不打开数据库。宿主在 `packages/plugin-host` 里实现这些接口。

## 已决定的事和主要风险

已经确定的有四件：Markdown 文件是唯一事实来源；客户端用 Tauri、Vite、React 和 CodeMirror 6；插件放在沙箱里并用清单声明权限；仓库是一个 monorepo。

主要风险：

- sqlite-vec 要在 Tauri 的各个桌面平台上编译和打包。
- 上万篇笔记的首次索引会花时间，嵌入调用也会产生费用。只对改动过的块重新嵌入，并把进度放在后台。
- 插件 API 一旦有第三方插件就不能随便改。所以现在标成 preview v1，等三个官方插件都接上之后再冻结。
